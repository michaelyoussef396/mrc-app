## Rulings — precedent

Standing rules established by a decision on a specific run, recorded here so the next
run that hits the same wall does not have to re-litigate it.

**Reasoning-level catches are a separate category from the code-level record (Michael, 2026-09-08).**
The reviewer's standing record — 13 false flags to a handful of real fixes — was built on findings
about *code*. Two catches on the equipment-days stack were not that: in round 1 Codex showed that
absent/0 parity tests compared the modified engine against itself and therefore proved nothing about
historical parity; in round 2 it showed that a constant CC had introduced, commented, filed in
`docs/TODO.md` and described to Michael as an "arithmetic-overflow sentinel" was nothing of the kind.
Neither was a defect a test would have caught — both were CC's *reasoning* about its own work, stated
confidently and wrong, and in both cases CC had already written the claim into tracked files. Count
these separately when judging whether a review round earns its cost: a reviewer that only ever
re-checks code would have passed both.

**An out-of-scope judgement that goes unrecorded is the same shape (Michael, 2026-09-08).**
Building the Unit B2 fix, CC noticed that subfloor treatment time feeds the same derived hours
as the areas and therefore carries the identical staleness, judged it out of scope for the unit,
and wrote it down nowhere. Codex resurfaced it as a finding on the next round. The defect is not
the miss — scoping is a legitimate call — it is that the call left no trace, so nothing but a
reviewer could recover it, and a reader of the fix would reasonably conclude the input set was
complete. **Record the boundary you drew and why, in the session log or the row, at the moment
you draw it.** An unrecorded "not now" is indistinguishable from "not noticed", and both read to
the next session as "already handled".

**Reviewable surface excludes byte-identical restores** (Michael, 2026-09-05, on
`8984fed`). A byte-identical restore of an unchanged tracked file is excluded from the
~150-line reviewable-surface count in the entry gate. The reviewer still receives the
file as context — it is not withheld — but only new or modified logic counts toward
the limit. Applied on `8984fed`: 166 raw lines, ~42 reviewable, because 124 of them
were a restore of a file that had been running unchanged for days. Without this rule
the commit would have failed entry condition 4 at 166 > ~150, and the review that
found three HIGH bypasses would never have run.
